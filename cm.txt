Inbound call presentation, live inbound dashboard, direction filter

The softphone auto-answered every incoming SIP leg. That is correct for a leg
the PLATFORM dialed to bridge an outbound call the agent already started --
prompting there would be a pointless extra click -- but wrong for a real
customer, who would be connected to an agent that never agreed to take the
call. The backend now marks genuine inbound legs with an X-Inbound-Call header
on the INVITE, and only those are presented for Answer/Decline. client_state
cannot serve this purpose: it returns on webhooks to the backend, never to the
SIP client.

IncomingCallPanel shows the caller, campaign, and whether this person has
contacted the team before, without exposing anything about the prior
conversation. Declining ends the leg, which returns the agent to rotation so
the caller can be offered to someone else rather than being stranded.

Live Inbound dashboard polls queue and active calls together in one request, so
the two halves can never be shown from different moments. Waits over a minute
are highlighted, and a caller waiting for a specific agent is marked as a
callback -- a different situation from one anyone can take.

Call Recordings gains a Direction filter; inbound and outbound recordings share
the same fault-tolerant pipeline and are told apart by the direction recorded
on the session.

No change to the working outbound call, audio, or recording paths.
